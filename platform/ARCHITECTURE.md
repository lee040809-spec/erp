# 业务模块与维护边界

## 前端

页面负责组合模块及管理页面状态；接口调用留在 services 或对应业务模块，金额计算、日期转换等纯逻辑留在 utils。

| 目录 | 主要职责 |
| --- | --- |
| front/src/features/orders | 订单复制、日期继承、按账号和公司保存草稿 |
| front/src/features/production-records | 办理零件导航、工序计划变更提示、生产记录更正 |
| front/src/features/accounting | 经营数据展示、补价、费用归属、分批送货对账及对账单明细 |
| front/src/features/drawings | 图纸管理、预览、历史引用、打印，共用一个预览与下载入口 |
| front/src/features/suppliers | 供应商类型选项、标签；沿用既有供应商编辑和外协选择组件 |
| front/src/features/system | 运行环境及备份状态展示 |
| front/src/hooks | 请求状态、保存保护、账号切换边界、筛选与滚动位置等共用行为 |

本地保存的草稿、筛选和滚动位置按账号与公司隔离。延迟回调和清理回调必须捕获原存储键，不能执行时才读取当前登录账号。公司编号 0 是有效值。

## 后端

- handlers：解析接口请求、权限与响应。共用业务规则放到相应业务包，避免接口之间直接调用。
- accounting：月份锁、待补价转产值、送货对账。`LockMonthStatus` 共用月份行锁 SQL。补价和订单保存通过 `WithPricingMonths` 先按年月锁定月份，再锁订单／零件；锁定业务数据后以当前读复核待补价月份，发现新月份必须回滚后重试，不能持有业务锁再补锁月份。重试恢复原输入，仅重试明确回滚的范围变化、死锁或锁等待超时，不重试网络断开等提交结果不明的错误。
- productionflow：按数量跟踪的生产工序、批次及数量约束。
- outsourcing：外协下单、发出、回厂、不合格处置、结算及供应商校验。
- repository/models：数据读取、保存与数据模型；订单补价复用 accounting，不在前端另算记账结果。
- runtimeinfo：只读运行及备份元信息，不返回数据库密码或备份文件内部路径。

产值按合格完工数量与已确认单价计算，超出订单数量的备用件不计产值。尚未补价的合格及交货记录可以保留，补价后归回原完工月份；已定价快照不随订单改价被重写。订单填写费用是参考，经营结余仍依据实际费用记录。

## 数据结构与验证

- 经营核算增量结构只在 `go-server/internal/accounting/schema.sql` 维护，由迁移工具与临时表测试共用；提交源码时不能遗漏此嵌入资源。
- 生产流转和供应商结构由 `go-server/internal/workflowmigration/schema.go` 维护。历史兼容 SQL 文件不能仅因内容相近而删除。
- 一般数据库集成用例按需执行，使用单连接临时表覆盖业务表。并发用例 `TestPricingConcurrencyIsolatedDatabase` 必须使用独立的 `erp_audit_test_` 数据库及真实共享表，显式设置 `RUN_PRICING_CONCURRENCY=1`；多个独立连接在 REPEATABLE READ 下验证。普通 `go test ./...` 默认跳过这些集成用例，不能代替数据库联动或并发验收。
- 发布源码前检查类型、前端回归与构建、Go 测试与 vet，以及本次涉及的临时表集成用例。
